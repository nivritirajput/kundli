## How to publish

1. In the repository, delete the old hashed files from the previous release (`engine.*.js`, `app.*.js`, `app.*.css`, `content.*.js`, `cities.*.js`, `phase3.*.js`) **after** uploading the new ones — or keep the previous set for a day so pages that are already open can still lazy-load their Phase 3 bundle.
2. Upload all files above (replace `index.html`, `sw.js`, `manifest.webmanifest`; add `fonts/` and `icons/`).
3. Old single-file visitors are upgraded automatically: the next visit fetches the small new `index.html`; there was no service worker before, so nothing stale can hold them. Saved people and settings (browser localStorage, same address) are kept.
4. Visitors of a previous multi-file release: the service worker is network-first for `index.html`, installs the new version at once (skipWaiting + clients.claim) and the page shows “New version available — tap to refresh”.

## Fallback

`node build.js --single` writes `dist-single/index.html`, the old one-file page (about 1.6 MB, everything inside). Publishing it as `index.html` also removes any service worker left by the multi-file build (it unregisters itself), so a rollback is safe. `node build.js --legacy` additionally writes it to the project root `index.html`.

## Notes

- Fonts: Noto Serif, Noto Serif Devanagari, Noto Sans, Noto Sans Devanagari, Noto Sans Symbols, Noto Sans Symbols 2 — SIL Open Font License 1.1 (`fonts/OFL.txt`, `fonts/README.txt`), subset to the characters the app uses.
- The only third-party request is the optional Google Fonts stylesheet (Baloo 2 + Nunito) for screen headings; without it the app falls back to system fonts. The print booklet uses only the bundled fonts.
- The Phase 3 bundle (`phase3.*.js`) is loaded only when a Phase 3 screen (Systems › Jaimini/KP/Varshaphal/Lal Kitab/other dashas, Prashna, Rectify) or the full PDF booklet is opened; the service worker caches it then.
